# 工作流程

```
capture ──► shots/c*.png       每屏一张，固定画布
         └► ocr/c*.json        Vision 的逐行结果（窗口坐标）
         └► build/screens_*.json  每屏解析出的消息

assemble ─► build/messages.json  跨屏拼接后的时间线

render ──► outputs/*.md / *.html + images/
```

## 1. 采集（capture）

- `wxwin` 通过 CGWindowList 找到微信窗口，`screencapture -l <id>` 抓窗口（被遮挡也能抓）
- `wincrop` 把截图裁到窗口内容，并**缩放到固定 1632×1948**
- `ocrfast`（Swift + Vision）对**整张截图**做 OCR

**坐标只有一套**：截图是固定画布，OCR 框就是窗口坐标，偏移恒为 0。
早期版本为了省几十毫秒把 OCR 裁到聊天区，结果产生第二套坐标，重解析时一错位，
左侧会话列表的文字就被当成聊天内容——所以现在不做裁剪。

- `wxscroll` 用 CGEvent 向上滚动可视高度的 50%（留一半重叠给拼接）

## 2. 单屏解析（wxparse）

1. **找布局**：消息区左右边界、顶部/底部（避开标题栏和输入框）
2. **按填色找气泡**：自己的绿色 `(176,240,167)`、对方的灰色 `(238,238,240)`
3. **文字 vs 图片**：气泡色的像素占比 ≥0.45 一定是文字气泡；
   图片（包括"聊天截图"）远低于这个值。颜色先判，几何只做兜底
4. **引用**：靠竖线定位引用块，挂在它上方那条消息上，正文从真实消息里复制
5. **表情**：在气泡内用模板比对找 108 个微信表情，定位后把 token 插进文字对应位置
6. **时间戳**：居中的短行，识别成 `timestamp`

## 3. 拼接（assemble）

- 用行像素指纹估滚动位移，再用文字锚点校正
- 只取"在上屏没完整出现过"的条目，避免重复
- 长于一屏的消息：上半屏 + 下半屏各取一半，按段落边界合并
- 时间戳先按显式日期锚定，再用相邻日期正推/反推，过滤 45 天以外的离群点

## 4. 输出（render）

- Markdown：按日期分段，`**说话人** · HH:MM：` + 正文
- HTML：同样的数据，双栏气泡、图片 base64/相对路径内嵌、可全文搜索
- 每个 emoji token 对应一张从截图裁出的图片（裁的是表情的**饱和色块**，
  汉字是深灰不饱和，所以不会把相邻字的半边裁进来）

## 为什么不用数据库解密

微信的聊天数据库是加密的，解密需要动客户端或注入，风险和维护成本都高。
截图 + OCR 的代价是可能有错字，但换来的是：不动微信、不需要密码、
任何版本都能用、出错只影响文字不影响电脑。
